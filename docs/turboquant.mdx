---
title: TurboQuant
---

TurboQuant is Ollama's compressed KV-cache path for the new engine. It reduces KV memory growth during long-context generation without changing the model's GGUF weight quantization.

In this branch, `tq25` and `tq35` now resolve to the paper-faithful TurboQuant path by default:

- deterministic random orthogonal rotation
- scalar Lloyd-Max quantization in the rotated basis
- key-side 1-bit QJL residual correction for inner-product scoring
- value-side MSE quantization only

TurboQuant is KV-cache compression only.

## Status

This branch currently exposes:

- `reference_wrapper`: the paper-faithful codec and Go-side wrapper cache path
- `native_backend`: the native-engine migration lane, introduced incrementally with explicit guards and status reporting
- `experimental` lanes: `tq25`, hybrid/native rollout work, and future `turbo4` or adaptive/per-layer ideas remain guarded

Wrapper-mode runs are still the reference lane. Do not treat them as proof of backend-native KV memory savings until the backend owns the packed KV payload directly.

## Rollout Presets

This branch does not recommend one universal TurboQuant mode. Use the support tier and runtime metadata to pick a rollout lane:

- `safe`: recommend symmetric `tq35/tq35` on the primary validated architecture families and `support_tier=safe`
- `conservative`: recommend `q8_0-K + tq35-V` only where the runtime still reports V-side TurboQuant support and no fallback
- `experimental`: `tq25`, `tq4` aliases, adaptive/per-layer K ideas, and native-migration paths stay behind explicit warnings

Current conservative guidance is intentionally narrow. Some asymmetric pairings still fail production-style correctness checks, so pairings outside the validated set should be treated as experimental even if they run.

## Recommended Pairings

Validated recommendation set in this branch:

- `tq35/tq35` on supported `safe` architecture families
- `q8_0-K + tq35-V` as the only first-class conservative asymmetric pairing, and only when runtime FA/path support keeps V in TurboQuant instead of falling back

Guarded or experimental-only pairings:

- `tq25/tq25`
- `tq25/tq35` or `tq35/tq25`
- arbitrary asymmetric mixes such as `q4_0-K + tq35-V`
- `tq4` / `turbo4` aliases
- adaptive/per-layer K compression

Those modes may still be useful for investigation, but this branch does not describe them as production-safe recommendations.

This branch includes:

- `turboquant/`: codec, packing, decode, scoring helpers
- `kvcache/turboquant.go`: KV cache storage, fallback decode, compressed-K handoff

## How To Use It

### One run

Use the recommended mode:

```shell
ollama run gemma3 --turboquant
```

Choose a specific TurboQuant preset:

```shell
ollama run gemma3 --turboquant=tq35
ollama run gemma3 --turboquant=tq25
```

Disable it explicitly for one run:

```shell
ollama run gemma3 --turboquant=off
```

### API

Set `options.kv_cache_type` on `/api/generate` or `/api/chat`:

```json
{
  "model": "gemma3",
  "prompt": "Explain TurboQuant.",
  "options": {
    "kv_cache_type": "tq35"
  }
}
```

Asymmetric overrides are also supported:

```json
{
  "model": "gemma3",
  "prompt": "Explain TurboQuant.",
  "options": {
    "kv_cache_type_k": "q8_0",
    "kv_cache_type_v": "tq35"
  }
}
```

The runtime reports the resolved mode and algorithm in the final response metrics:

- `resolved_kv_cache_type`
- `resolved_kv_cache_type_k`
- `resolved_kv_cache_type_v`
- `kv_algo_resolved`
- `kv_algo_resolved_k`
- `kv_algo_resolved_v`
- `kv_cache_path`
- `kv_cache_path_k`
- `kv_cache_path_v`
- `kv_symmetric`
- `kv_asymmetric`
- `fallback_reason`
- `turboquant_path_kind`
- `support_tier`
- `preset_requested`
- `preset_resolved`
- `preset_warning`
- `pairing_validated`
- `experimental_lane`

Use the effective K/V mode and these runtime fields for comparisons. If requested and effective modes differ, the effective mode is the truth for rollout and benchmark claims.

### Modelfile default

To make a selected model default to TurboQuant:

```text
FROM gemma3
PARAMETER kv_cache_type tq35
```

More aggressive compression:

```text
PARAMETER kv_cache_type tq25
```

Inspect the stored default with:

```shell
ollama show --parameters your-model
```

### Environment fallback

If neither the request nor the model specifies a KV mode, Ollama falls back to `OLLAMA_KV_CACHE_TYPE`.

`OLLAMA_KV_CACHE_TYPE_K` and `OLLAMA_KV_CACHE_TYPE_V` can override the K or V side independently.

`OLLAMA_TURBOQUANT_PRESET` can be set to `safe`, `conservative`, or `experimental` to drive rollout guidance and warnings without changing the actual requested K/V types.

## Mode Precedence

The effective KV cache mode is resolved in this order:

1. request side-specific override: `--cache-type-k`, `--cache-type-v`, `options.kv_cache_type_k`, `options.kv_cache_type_v`
2. request shorthand: `--turboquant` or `options.kv_cache_type`
3. model default: `PARAMETER kv_cache_type ...`
4. environment: `OLLAMA_KV_CACHE_TYPE_K`, `OLLAMA_KV_CACHE_TYPE_V`, then `OLLAMA_KV_CACHE_TYPE`
5. implicit default: `f16/f16`

## Compatibility And Limitations

- TurboQuant applies to generation and chat paths only.
- The legacy llama runner still rejects TurboQuant modes.
- TurboQuant modes require the new engine path.
- Quantized KV modes require flash attention support.
- `reference_wrapper` remains the stable comparison lane for this branch.
- `native_grouped_scaffold` and `native_backend` should not be assumed wire-compatible across distributed/RPC boundaries unless both ends match layout kind, layout version, and path semantics.
- `turbo4` and adaptive/per-layer K work are not promoted to production-ready guidance in this branch.

## TurboQuant And GGUF Quants

TurboQuant is KV-cache compression. It does not replace the model's GGUF weight quantization.

That means you can use TurboQuant on top of the GGUF model-weight formats that Ollama already loads successfully through the new engine, for example:

- `F16`
- `Q8_0`
- `Q6_K`
- `Q5_K_M`
- `Q5_K_S`
- `Q4_K_M`
- `Q4_K_S`

This is not a separate closed compatibility matrix. TurboQuant overlays the normal GGUF model-weight format you already use.
